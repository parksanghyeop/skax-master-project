# Phase 2 — 테스트 및 고도화: 안전장치와 숫자

## 목표

PoC 슬라이스를 **전체 파이프라인 + 품질 게이트**로 확장하고,
평가 하네스로 **개선을 숫자로 증명**할 수 있는 상태를 만드는 것.

## 시작 의식 — 코드보다 먼저

1. `docs/poc-findings.md`의 "설계 수정 필요"를 훑고, 확정할 것은 **ADR로 먼저** 기록
2. ADR-0010(테스트 작성 루프 LangGraph 전환 + interrupt)이 아직 없으면 이번에 쓴다
3. 문서·스킬에 남은 구설계 표기(`delegate_exploration`, 직접 while 루프)를 발견하면 갱신

## 범위 (M4 → M7)

- **M4 코드 그래프**: Neo4j, 확정 엣지 3종(선언·생성·COVERS는 JaCoCo 실측) 먼저. `CALLS`는 confidence 붙여 후순위. `query_code_graph` 스텁을 실물로 교체 — 쿼리 6종, 반환 800토큰 상한
- **M5 파이프라인**: 변경 추출(git diff→심볼), 의도 분류(대분류+구체 분석 **한 호출**), 조치 결정(경로표 + 작업 지침서 조립). 경로표에 "불확실→ask" 행 포함
- **M6 품질 게이트 5종**: ① assert AST 비교(기존 assert 훼손=탈락, 판단하지 않고 사람 목록으로) ② 스킵 어노테이션 ③ 파일 허용 목록 ④ 커버리지 — 변경 라인 80%/분기 70% 기본값, **설정 파일로 조정**, 수정 건은 회귀 금지, 탈락 사유에 미실행 분기 명시 ⑤ PIT 뮤테이션. 탈락→사유 반환→재시도 최대 3회→사람 확인 목록
- **interrupt 실연결**: 실패 분류(자동 수정 가능/판단 필요/불가능) + 판단 필요·한도 도달 시 LangGraph interrupt로 정지, resolve로 재개. 힌트는 다음 시도 프롬프트에 주입
- **M7 평가 하네스**: Defects4J 서브셋(1개 프로젝트 20~40건) + 테스트 스트리핑, EvoSuite 베이스라인, 지표(검출률·커버리지·뮤테이션 점수·assert 약화 0건·에스컬레이션율·비용). 프롬프트/모델/데이터셋 버전을 수치에 묶어 기록

## 게이트 불변식 테스트 — 이 단계의 핵심 테스트

악의적 시나리오를 카세트로 만들어 게이트가 막는지 검증한다. 최소 세트:
- 모델이 기존 assertEquals를 assertNotNull로 바꾼 응답 → 탈락해야 함
- 모델이 @Disabled를 붙인 응답 → 탈락해야 함
- 허용 목록 밖 소스 파일을 수정한 응답 → 탈락해야 함
- assert 없는 100% 커버리지 테스트 → 뮤테이션에서 탈락해야 함
이 테스트들이 초록이면 게이트가 사양대로 작동한다는 증거가 된다.

## 고도화 규칙

- **수치 없는 개선 금지** — 프롬프트·전략 변경은 하네스 전/후 수치와 함께 보고. "좋아진 것 같다" 금지
- 실험은 시드·카세트 고정으로 재현 가능하게. 결과는 `evals/results/`에 버전과 함께
- 모델 3종(Kimi/Qwen/GLM) 비교는 같은 문제 세트로만

## 관문 (3단계 진입 조건)

- 게이트 불변식 테스트 전부 통과
- Defects4J 서브셋에서 베이스라인 수치 확보 (EvoSuite 비교 포함)
- refactor+실패 케이스가 실제로 escalate→resolve→재개까지 돈다
