## 1. 문제와 목표

코드를 고치면 테스트도 따라 고쳐야 하는데, 이 일은 반복적이고 미루기 쉽다. LLM에게 통째로 맡기면 두 가지가 위험하다. 기존 테스트의 기대값을 몰래 고쳐 "통과"시키는 것, 그리고 리팩터링인데 테스트가 깨진 상황(동작이 실제로 바뀐 것)을 덮는 것이다.

그래서 목표를 이렇게 잡았다.

1. 테스트가 없는 메서드에 **실제로 실행되고 버그를 잡는** 테스트를 만든다 (커버리지·뮤테이션으로 실측).
2. 코드 변경의 **의도**(버그 수정 · 리팩터링 · 새 기능)를 판단해 알맞은 조치를 하되, 조치의 **길은 규칙표**가 정한다.
3. 리팩터링인데 테스트가 깨지면 기대값을 고치지 않고 **사람에게 넘긴다**.
4. 변경된 메서드를 **호출하는 곳까지** 시험 범위에 넣는다 (2026-09 확장).

## 2. 최종 아키텍처

그림 1(Agent Architecture) · 그림 2(Detailed Architecture) · 그림 6(Project Structure) 참조.

### 2.1 층 구조와 의존 방향

```
cli → core ← adapters/java · graph · llm · sandbox
```

- **core**: 포트(인터페이스) 9종, 규칙표·변경 대응 분석, 고유 도구 6개, 작성 루프, 게이트 계약. Java·Maven이라는 이름을 모른다(R1). `tests/test_layering.py`가 문자열 검사로 강제한다.
- **adapters/java**: 포트의 Java·Maven 구현 — 정규식 파서, 재료 수집, git 변경 추출, 그래프 빌더, JaCoCo·PIT 실측, 게이트, 테스트 쓰기·병합.
- **graph**: 코드 그래프 — 노드 2종(Class·Method), 엣지 4종(DECLARES·CREATES·COVERS 확정 + CALLS 추정). 인메모리 저장소와 Neo4j 저장소가 같은 계약을 따른다.
- **llm**: LLM 호출의 유일한 통로(R7) — 게이트웨이 HTTP, 테스트 작성, 의도 분류, 임베딩, 호출 기록·재생, 토큰 합산, 시크릿 가림.
- **sandbox**: 실행 장치 — 이 PC의 Maven·JDK(기본) 또는 네트워크를 끊은 Docker 컨테이너.
- **cli**: 명령 조립과 화면 출력만. 판단 로직이 없다.

### 2.2 LLM이 있는 두 자리와 안전장치

| 구분 | 무엇 | 왜 일반 코드인가 |
|---|---|---|
| LLM ① 의도 판단 | 변경 한 건마다 분류·확신도·근거·분석을 JSON으로 | 사람이 화면에서 근거를 읽고 반박할 수 있게 |
| LLM ② 테스트 작성 | 쓰기 → 실행 → 진단 반복(≤8회, 4회마다 사람에게) | 실행 결과가 곧 피드백 |
| 규칙표 | (의도 × 기존 테스트 상태) → 만들기 / 할 일 없음 / 사람 확인 | 길을 잘못 고르면 기대값이 바뀌는 사고 — 표 조회만 한다(R2) |
| 게이트 6종 | assert 훼손 · 스킵 · 파일 범위 · 커버리지(80/70) · 뮤테이션 · 회귀(수정 전 코드에서 실패해야) | "좋은 테스트인가"를 판단하지 않고 규칙 위반만 본다. 탈락 사유는 모델에게 돌아간다 |
| 반복 상한·사람 개입 | 시도 ≤8, 게이트 재시도 ≤3, 같은 실패 2회면 묻기 | 무한 재시도 제거 |

### 2.3 코드 그래프와 영향 범위 (그림 4)

- 확정 관계 3종은 조치 결정의 입력이 된다 — 특히 COVERS(커버리지 실측)가 "기존 테스트가 있는가, 통과하는가"의 근거다.
- **CALLS(호출 관계)는 정적 추정**이라 확신도(high/medium)를 붙이고, 화면·작업 지침서·`--impact` 파생 생성 건에만 쓴다. 규칙표에는 넣지 않는다. 호출자의 테스트가 정말 대상을 실행하면 COVERS가 이미 실측하기 때문이다.
- Neo4j가 없으면 그 자리에서 파싱해 인메모리 그래프로 답한다. 그래프는 필수가 아니다.

### 2.4 기억 — 판단 메모

사람이 `cta resolve`로 내린 결정은 상황 요약(커밋 메시지 첫 줄 + 대상 + 분석, 자연어)과 그 임베딩 벡터와 함께 저장된다. 다음 `maintain`은 같은 메서드·클래스 이름 일치를 먼저, 빈 자리를 코사인 유사도 상위로 채워 최대 3건을 의도 판단 프롬프트에 "참고"로 붙인다. 참고일 뿐 규칙표를 바꾸지 못한다(불변식 테스트로 고정).

"코드 RAG는 벡터가 아니라 그래프"가 이 설계의 핵심이다. 구조 질의(누가 호출하나)는 그래프가 정답을 주고, 임베딩은 자연어(판단 메모)에만 쓴다. 코드 본문을 임베딩해 유사도로 영향 범위를 찾는 방식은 닮은 코드와 부르는 코드를 혼동하므로 채택하지 않았다(ADR-0026).

## 3. 명령과 사용 흐름 (그림 3 · 그림 5)

| 상황 | 명령 | 흐름 | 종료 코드 |
|---|---|---|---|
| 테스트 없는 클래스 | `cta generate --class C [--max-methods N] [--fast]` | 재료 수집 → 작성(LLM) → 게이트 → 제안 | 0 / 2 / 3 |
| 커밋했으니 테스트를 맞춰야 한다 | `cta maintain --diff HEAD~1 [--intent 의도] [--message …] [--impact]` | 변경 추출 → 의도 판단(LLM) → 기존 테스트 실행 + 영향 범위 → 규칙표 → 만들기 / 없음 / 사람 확인 | 0 / 2 / 3 |
| 멈춘 항목에 답한다 | `cta resolve <id> --intended \| --test-issue \| --proceed \| --as 의도 \| --skip` | 저장 항목 읽기 → 재개(실패 테스트만 제자리 교체) → 게이트 → 제안 + 판단 메모 | 0 / 2 / 3 |
| 검토·반영 | `cta diff` → `cta apply [이름 \| --all]` / `cta discard` | 이때만 `src/test`에 쓴다 | 0 |
| 그래프·평가·시연 | `cta graph [--coverage]` · `cta eval [--intents]` · `cta demo` | Neo4j 적재 · 검출률/정확도 실측 · 저장된 호출 기록 재생(비용 0) | 0 / 1 |

종료 코드 3은 실패가 아니라 "사람 확인 필요"다. CI는 이 값으로 분기한다.

## 6. 운영과 보안

- 서버 주소·API 키는 `.env`(gitignore) 또는 환경변수로만 받는다. 코드·커밋·저장된 호출 기록·로그에 남기지 않으며, 화면·로그의 키 모양 문자열은 `****`로 가린다.
- 생성물은 `cta apply` 전까지 소스에 닿지 않는다. 사람이 `cta diff`로 검토한다.
- 기본 실행 장치는 이 PC의 Maven·JDK라 격리가 없다. 남의 코드·CI에서는 `--runner docker`(네트워크 차단 컨테이너)를 쓴다.
- LLM 호출은 전부 기록·재생할 수 있어 CI는 재생 모드로 돈다. 기록이 어긋나면 실호출로 폴백하지 않고 실패한다.
- 토큰 예산(`cta.toml [budget]`)을 넘으면 실행을 멈춘다.

- Maven 단일 모듈 · JUnit 5만 지원. 파서가 정규식 근사라 제네릭·중첩 클래스가 많은 코드에서 빗나갈 수 있다.
- 호출 관계는 정적 추정이라 상속·리플렉션·DI 경유 호출은 잡지 못한다. 그래서 규칙표에 넣지 않는다.
- 판단 메모 유사도 기준치(0.35)는 실측 몇 건으로 정했다. 사용이 쌓이면 조정해야 한다.
- 이 PC에는 Docker·Neo4j가 없어 `--runner docker`와 `cta graph`(Neo4j 적재)는 이번 점검에서 실행하지 못했다. 코드 경로는 단위·통합 테스트(마커)로만 확인했다.
- 확신도는 모델이 매긴 값이며 코드는 이 값으로 분기하지 않는다.

**다음 단계**

1. Docker·Neo4j가 있는 환경에서 `--runner docker`와 `cta graph --coverage` 실측.
2. 결함 세트에 실사용 중 놓친 변경을 추가해 편향을 줄인다.
3. 호출자 경유 테스트의 효과를 결함 세트로 수치화(`--impact` 전/후 검출률).
4. 멀티모듈 Maven, tree-sitter 기반 파서 검토.
