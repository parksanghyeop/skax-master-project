# ADR-0016: 대화 압축을 구현하지 않는다 — 작성 루프는 누적 대화가 아니다

- 상태: 승인 (2026-09-06). phase3 스킬 M8의 "대화 압축: 원문 유지 / 요약 대상 구분 구현"
  항목을 **구현 없이** 닫는 결정. "안 했다"가 아니라 "필요 없음을 구조와 테스트로 확인했다"다

## 배경

v4와 3단계 스킬은 긴 에이전트 대화에서 오래된 도구 출력·폐기 시도를 요약해 토큰을 줄이는
"대화 압축"을 요구한다. 전제는 시도마다 메시지가 누적되는 멀티턴 대화다.

## 결정

구현하지 않는다. 현재 작성 루프(`core/writer_graph.py`)는 **매 시도가 단발 프롬프트**다.

- 프롬프트 빈칸은 다섯 개다(`llm/prompts/write_test.md`): 작업 지침서 · 수집된 정보 · 프로젝트 관례 ·
  **직전** 시도 코드 · **직전** 실행 실패. 옛 시도와 옛 실패는 프롬프트에 들어가지 않는다
- 스킬이 "원문 유지 대상"으로 꼽은 셋(규칙·현재 테스트 코드·직전 실패)만 이미 넣고 있고,
  "요약 대상"(오래된 도구 출력·폐기 시도)은 애초에 안 넣는다. "실패했다는 사실"은 상태의
  `attempts`와 사용자 질문 문구("N회 실패했다")로 유지된다
- 회차 기록 `history`는 화면 출력용이고 LLM에 가지 않는다

따라서 시도가 8회까지 가도 프롬프트 크기는 코드·실패 로그 길이로만 변하고 회차에 비례해 늘지 않는다.

## 근거(검증)

- `tests/test_writer_graph.py::TestPromptDoesNotAccumulate` — 세 번째 시도의 `last_failure`에
  직전 실패만 있고 첫 실패는 없다
- 실측(2026-09-03, SC-002): 1차 생성 5,911자 → 2차 5,853자. 2차 프롬프트는 1차 코드 + 실패 로그가
  더해진 만큼만 컸고, 전체 소요 토큰 16,704는 두 호출 합이다(`PoC구현.md` §4 검증 2 로그)

## 결과

- 3단계 범위에서 대화 압축 코드·설정·테스트를 만들지 않는다. 릴리스 체크리스트에는 이 ADR을 근거로 표기
- 다시 필요해지는 조건: 작성 루프를 도구 호출형 멀티턴(모델이 inspect·run을 스스로 부르는 방식)으로
  바꿀 때. 그때는 이 ADR을 폐기하고 압축 규칙을 새 ADR로 쓴다
