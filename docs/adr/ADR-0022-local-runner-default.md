# ADR-0022: 실행 장치 기본값은 로컬 — Docker 샌드박스는 `--runner docker`로 고른다

- 상태: 승인 (2026-09-07). ADR-0019(로컬 실행 모드는 `--fast`일 때만)의 기본값을 뒤집는다. R6 재정의
- 관련: v4 설계 6절(Docker 샌드박스), 사용자 결정 2026-09-07 "로컬 기준으로 진행"(발표·시연·설치 부담)

## 배경

지금까지 기본값은 Docker 샌드박스였고 로컬 실행은 `--fast`/`--runner local`로만 켰다(ADR-0019). 실측(테스트및고도화 §2.2)에서
Docker 경로의 비용은 컨테이너가 아니라 **Windows 바인드 마운트**였다 — Maven 1회 20~45초, 첫 실행 준비 5분. 로컬 실행은
같은 작업이 5~8초다. 시연은 Docker Desktop 기동과 이미지가 있어야 하고, 설치 안내도 Docker를 전제로 한다.
"남이 설치해서 쓰는" 3단계 목표와 발표 시연을 놓고 보면, 기본값을 로컬로 두고 격리를 선택지로 남기는 편이 맞다.

## 결정

1. **기본 실행 장치는 `local`**(이 PC의 Maven·JDK). `choose_runner(explicit, fast)`는 명시한 `--runner`가 이기고,
   없으면 항상 `local`이다. `--fast`는 더 이상 실행 장치를 바꾸지 않는다
2. **`--fast`의 뜻은 "무거운 게이트 생략"으로 돌아간다** — 커버리지·뮤테이션 게이트와 PIT 전후 측정을 건너뛴다.
   격리·게이트와 무관하다
3. **Docker 샌드박스는 `--runner docker`로 고른다.** 네트워크 차단·읽기 전용 캐시 마운트·준비 단계(`ensure_prepared`)는
   이 경로에서만 돈다. CI처럼 격리가 필요한 곳에서 쓴다. 코드가 두 장치 사이를 스스로 바꾸는 경로는 없다(ADR-0019 유지)
4. **`cta graph --coverage`와 `cta demo`도 같은 규칙**을 따른다(`--runner` 옵션, 기본 local). ADR-0019가 "Docker 유지"로
   남겨 둔 두 곳이다 — 시연이 Docker 없이 돌아야 하므로 로컬화한다
5. **R6 재정의**: "대상 코드는 실행 장치(`local` 기본 / `docker` 격리) 안에서 도구를 통해서만 실행한다. 디버깅 목적의
   임의 실행 금지. 코드가 실행 장치를 스스로 바꾸지 않는다." 로컬이 기본이므로 "로컬 실행 경고"는 정보 한 줄로 낮춘다
6. **준비물이 바뀐다**: Python + JDK 17+ + Maven(+ 게이트웨이 키). Docker는 선택. 로컬 모드는 사용자의 `~/.m2`를 쓰므로
   없는 의존성은 Maven이 온라인으로 받는다 — 사설 저장소·프록시 설정은 사용자의 Maven 설정을 따른다

## 잃는 것 (알고 받아들인다)

- 기본 실행에 **격리가 없다** — LLM이 만든 테스트가 사용자 권한·네트워크로 실행된다. 신뢰하는 코드베이스에서 쓰고,
  남의 코드·CI는 `--runner docker`
- JDK·Maven 버전이 사용자마다 달라 재현성이 낮아진다. 이미지 고정은 `--runner docker`에서만

## 검증

- 단위: `tests/test_local_sandbox.py` 선택 규칙(기본 local, `--runner docker` 명시, `--fast`는 장치 무관)
- 실기동(이 PC): 로컬 장치로 커버리지(JaCoCo)·뮤테이션(PIT) 측정이 도는지 — ADR-0019의 미검증 항목. 결과는 e2e-notes 9주차
- `cta demo`가 Docker 없이 재생되는지

## 결과

- 시연·설치 준비물에서 Docker Desktop이 빠진다. 반복 실행이 초 단위
- ADR-0019의 결정 1·2·4는 이 ADR로 대체된다. `LocalSandbox`·`Sandbox` 프로토콜·안전장치(R5, 테스트 폴더 밖 쓰기 금지,
  게이트 판정, 제안 보관)는 그대로다
