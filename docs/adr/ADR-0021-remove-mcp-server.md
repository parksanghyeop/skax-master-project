# ADR-0021: MCP 서버를 제거한다 — 진입점은 CLI 하나

- 상태: 승인 (2026-09-07). **ADR-0018(MCP 서버는 CLI 껍데기)을 폐기**한다
- 관련: phase3 스킬 M8 "MCP 서버" 항목, 사용자 결정 2026-09-07 "볼륨이 너무 커져 발표·시연이 어렵다"

## 배경

ADR-0018로 `cta/mcp/`(핸들러 130줄 + 서버 40줄, 도구 5개)를 넣었다. 동작은 했지만(in-process 등록·호출 확인)
Claude Code에서의 실호출은 끝내 측정하지 못했고, 산출물마다 "MCP 경로"라는 두 번째 진입점을 설명해야 했다.
발표에서 보여 줄 것은 `generate → maintain → resolve` 한 흐름인데 진입점이 둘이면 시연 경로와 설명이 늘어난다.
3단계는 "닫는 단계"다(E2E/README §0) — 어필용 확장이 닫기를 방해하면 뺀다.

## 결정

1. **`cta/mcp/`와 `tests/test_mcp.py`를 삭제한다.** `pyproject.toml`의 선택 의존성 `[mcp]`, 진입점 `cta-mcp`,
   패키지 목록의 `cta.mcp`도 지운다. CI 설치는 `pip install -e .`로 되돌린다
2. **문서에서 MCP를 뺀다** — README, 사용가이드 §14(삭제, §15 → §14), architecture(층 그림·모듈 표), contracts(MCP 층 절),
   E2E 산출물·최종보고·다이어그램(`mcp-path` 삭제, `e2e-architecture`·`e2e-status` 재렌더). 작업 기록(e2e-notes)과
   계획(작업목록)은 이력이므로 "구현 후 제거"로만 표기한다
3. **유지하는 것**: MCP를 계기로 고친 두 원칙은 MCP와 무관하게 옳으므로 남긴다 —
   cta.toml 값을 환경변수에 쓰지 않고 인자로 전달(오래 사는 프로세스 일반), 시크릿은 환경변수·.env만(ADR-0011)
4. 다시 필요해지면 ADR-0018과 커밋 `ecb7641` 시점의 `cta/mcp/`를 그대로 되살릴 수 있다 — 핸들러가 cli 함수를
   호출만 했으므로 core·cli 쪽에 되돌릴 흔적이 없다

## 결과

- 진입점은 `cta` CLI 하나. R4(에이전트 내부 도구 6개)와 "MCP 도구 5개"를 구분해 설명할 필요가 없어졌다
- 제품 코드 약 170줄, 테스트 6건 감소. 선택 의존성 없음 — 설치 안내가 `pip install` 한 줄로 돌아간다
- 릴리스 체크리스트의 "MCP 실호출" 항목은 조건에서 빠진다
