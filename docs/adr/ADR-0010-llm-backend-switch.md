# ADR-0010: LLM 백엔드 이원화 — 개발은 Claude API, 운영은 사내 게이트웨이

- 상태: 승인 (2026-09-01, 사용자 지시)
- 관련: v4 5절(기술 스택), 절대 규칙 R7, ADR-0001~0009(원문 미반입)

## 배경

v4 설계는 사내 LLM 게이트웨이(Kimi/Qwen/GLM)를 전제하지만, 개발 환경에서는
사내망에 접속할 수 없어 실호출 개발·검증이 막힌다. 사용자가 자신의 Claude 계정
(Anthropic API)을 개발용 백엔드로 쓰기로 결정했다.

## 결정

1. **LlmClient 구현을 provider로 선택한다.** `llm/config.py`가 설정을 읽어
   `claude`(Anthropic API, 개발) 또는 `gateway`(사내, 운영) 클라이언트를 만든다.
   호출부는 LlmClient 포트만 알므로 전환 시 코드 수정이 없다.
2. **설정·시크릿은 리포 밖에만 둔다.** 우선순위: 환경변수 > `.env`(리포 루트,
   **gitignore 대상**). 커밋되는 것은 `.env.example`(키 이름만, 값 없음)뿐이다.
   v4 6.6(시크릿은 환경변수로만)의 확장이며, 원격 레포에 자격 증명이 올라가는
   경로를 구조적으로 차단한다.
3. **Claude 클라이언트는 공식 `anthropic` SDK를 쓴다.** 인증 자동 해석
   (`ANTHROPIC_API_KEY` → `ant auth login` 프로필), 재시도·타입 오류 처리가
   내장돼 있어 stdlib 재구현보다 안전하다. 게이트웨이 클라이언트는 스펙 미확정이라
   stdlib urllib 유지.

## 결과

- 카세트(record & replay)는 provider와 무관하게 동작 — 녹음 시점의 모델 이름이
  요청 대조 키에 포함되므로, provider를 바꾸면 골든 카세트는 재녹음한다.
- 임베딩 보조 검색(v4 4.1 ④)은 개발 백엔드에서 불가(Anthropic API는 임베딩
  엔드포인트 미제공) — 2단계에서 게이트웨이 확인 전까지 보조 검색은 보류.
- 프롬프트·도구 설계는 두 백엔드 공용이므로, Claude로 개발한 프롬프트를
  게이트웨이 모델로 옮길 때 재평가가 필요하다(평가 하네스는 2단계).
