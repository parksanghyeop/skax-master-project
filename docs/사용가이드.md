# Code Test Agent 사용 가이드 (CLI)

Java 메서드를 지정하면 그에 맞는 JUnit 테스트를 자동으로 만들어 주는 에이전트를
터미널에서 직접 실행하는 방법을 설명한다. 이 문서만 보고 처음부터 끝까지 따라할 수 있게 썼다.

> 현재는 PoC 단계라 진입점이 스크립트 형태다(`scripts/generate_test.py`).
> 정식 CLI 명령(설치형, 전체 옵션)은 3단계에서 제공 예정.

---

## 1. 무엇을 하는 도구인가

`--target Calculator#divide`처럼 대상 메서드를 지정하면, 에이전트가 아래를 자동으로 수행한다.

1. 대상 메서드의 소스를 조사한다
2. 프로젝트의 기존 테스트 중 모양이 비슷한 것을 골라 참고 예시로 삼는다
3. LLM(사내 게이트웨이)이 테스트 파일 전체를 생성한다
4. **인터넷이 차단된 Docker 환경**에서 컴파일하고, 생성된 테스트만 실행한다
5. 실패하면 실패 로그를 들고 스스로 고쳐 재시도한다(최대 6회, 초과 시 이유를 보고하고 종료)
6. 통과하면 assert 없는 빈 테스트가 아닌지 기계적으로 검사한 뒤, 테스트 파일을 프로젝트에 남긴다

생성된 파일을 커밋할지는 **사람이 diff를 보고 결정**한다 — 에이전트는 제안까지만 한다.

## 2. 준비물

| 항목 | 확인 방법 |
|---|---|
| Python 3.11 이상 | `python --version` |
| Docker (데몬 실행 중) | `docker info` 가 오류 없이 출력되면 됨 |
| 사내 게이트웨이 API 키 (`atl-...`) | 사내 안내 문서 참조 |
| 대상 프로젝트 | Maven 단일 모듈(`pom.xml`), 기존 테스트 1개 이상 권장(아래 4.3 참고) |

Java·Maven은 PC에 설치할 필요 없다 — 전부 Docker 컨테이너 안에서 돈다.

## 3. 설치 (최초 1회)

리포지토리 루트에서:

```powershell
# 1) 가상환경 만들기 + 의존성 설치
python -m venv .venv
.venv\Scripts\pip install -e .
.venv\Scripts\pip install pytest ruff        # 개발·검증 도구 (실행만 할 거면 생략 가능)

# 2) 설정 파일 만들기 — 예시를 복사해 값을 채운다
copy .env.example .env
```

`.env`를 열어 세 값을 채운다 (macOS/Linux는 `cp`, 경로 구분자만 다르고 나머지는 동일):

```
CTA_GATEWAY_URL=      ← 게이트웨이 주소 (사내 안내 문서)
CTA_GATEWAY_API_KEY=  ← 본인 API 키 (atl-...)
CTA_LLM_MODEL=gpt-5   ← 사용할 모델 (생략 시 gpt-4.1)
```

> ⚠️ **`.env`는 절대 커밋하지 않는다.** gitignore에 이미 등록돼 있고, 키·주소는
> 이 파일과 환경변수로만 전달한다. `.env.example`에는 실제 값을 쓰면 안 된다.

설치 확인:

```powershell
.venv\Scripts\python -m pytest -q     # 54 passed 나오면 정상 (Docker·키 없이도 통과)
```

## 4. 실행

### 4.1 5분 체험 — 동봉된 예제 프로젝트로

리포에 실험용 Maven 프로젝트(`examples/demo`)가 들어 있다. 실제 LLM을 호출해
테스트가 없는 `divide` 메서드에 새 테스트를 만들어 보자:

```powershell
.venv\Scripts\python scripts\generate_test.py --project examples\demo --target "Calculator#divide"
```

최초 실행은 Docker 이미지·Maven 의존성 다운로드 때문에 몇 분 걸린다(이후엔 캐시로 수십 초).
성공하면 이렇게 끝난다:

```
결과: passed  (시도 1회, 41초)
실행: 통과
품질: 통과: 새 테스트, assert 5개

생성 파일: ...\examples\demo\src\test\java\com\example\demo\CalculatorDivideTest.java
내용을 git diff 등으로 검토한 뒤 커밋 여부를 결정하라.
```

> LLM 호출 없이 흐름만 보고 싶으면: `.venv\Scripts\python scripts\demo_golden.py`
> (저장된 호출 기록을 재생하므로 비용 0, 결과 항상 동일)

### 4.2 내 프로젝트에 사용하기

```powershell
.venv\Scripts\python scripts\generate_test.py `
  --project C:\work\my-service `
  --target "OrderService#cancel"
```

| 옵션 | 필수 | 설명 |
|---|---|---|
| `--project` | ✅ | Maven 프로젝트 루트 (pom.xml이 있는 폴더) |
| `--target` | ✅ | `클래스#메서드` 형식. 클래스 이름만 쓰면 클래스 전체 대상 |
| `--test-class` | | 생성할 테스트 클래스 이름. 기본: `<클래스><메서드>Test` (예: OrderServiceCancelTest) |
| `--instruction` | | 지침에 덧붙일 요구. 예: `"금액이 음수인 경계값도 시험하라"` |
| `--model` | | 이번 실행만 다른 모델 사용 (예: `gpt-4.1-mini`) |
| `--warmup-test` | | 최초 준비 단계에서 실행할 기존 테스트 지정 (기본: 자동 탐지) |

동작 순서와 소요 시간:

1. **준비 (프로젝트당 최초 1회, 수 분)** — 의존성을 전부 내려받아 `<프로젝트>/.cta/m2repo`에
   캐시하고, 기존 테스트 1개를 실제로 돌려 캐시를 완성한다. 이후 실행은 이 단계를 건너뛴다
2. **생성·검증 (수십 초~수 분)** — 생성→컴파일→차단 환경 실행→품질 검사.
   실패하면 자동 재시도(최대 6회)
3. **결과** — 통과 시 테스트 파일이 프로젝트에 남는다. `git diff`로 확인 후 채택/삭제

종료 코드: `0` 통과 / `1` 설정·입력 오류 / `2` 테스트를 통과시키지 못함(이유 보고 출력).

### 4.3 알아둘 제약 (PoC 범위)

- **"새 테스트 생성" 한 가지만 한다.** 기존 테스트 수정, git 변경 감지 기반 자동 판단,
  커버리지·변이 검사 등은 2단계에서 추가된다
- Maven **단일 모듈** 프로젝트 기준이다 (Gradle·멀티 모듈 미지원)
- 최초 준비 단계의 "예열"에 기존 테스트가 1개 필요하다. 테스트가 하나도 없는 프로젝트면
  간단한 테스트를 하나 추가하거나 `--warmup-test`로 지정할 수 있는 상태를 만들어야 한다
- 생성 테스트가 통과해도 **품질의 최종 판단은 사람 몫**이다 — assert가 의미 있는 검증인지 확인할 것

## 5. 문제가 생기면 (자주 겪는 순서대로)

| 증상 | 원인과 해결 |
|---|---|
| `failed to connect to the docker API ...` | Docker Desktop이 꺼져 있다. 실행 후 `docker info`로 확인하고 재시도 |
| `환경변수 CTA_GATEWAY_URL·CTA_GATEWAY_API_KEY가 필요하다` | `.env`가 없거나 값이 비어 있다. 3번 설치 절차 확인 |
| `게이트웨이 호출 실패 ... 401/403` | API 키가 틀렸거나 만료됨. 키 재발급 후 `.env` 갱신 |
| 준비 단계가 몇 분째 안 끝남 | 정상이다(의존성 전체 다운로드). 프로젝트당 최초 1회만 |
| `준비 실패` + 다운로드 오류 로그 | 사내망 프록시 등으로 컨테이너가 Maven 저장소에 못 나감. 네트워크 환경 확인 |
| `빈 selector — 전체 테스트 실행은 금지다` | 의도된 안전장치다. 전체 테스트 실행은 지원하지 않는다 |
| 한글 출력이 깨짐 (Windows) | 실행 전 `$env:PYTHONIOENCODING='utf-8'` 설정 |
| `카세트/기록 없음` 류 메시지로 pytest 실패 | 저장된 LLM 호출 기록 파일(`evals/golden/`)이 지워짐. `git checkout evals/golden/`으로 복구 |
| 결과가 `2` (통과 못 함) | 출력의 "한계 보고"에 이유가 있다. `--instruction`으로 힌트를 주고 재실행하거나, 대상 메서드가 테스트 가능한 구조인지 확인 |

## 6. 명령 모음

```powershell
# 실사용: 테스트 생성
.venv\Scripts\python scripts\generate_test.py --project <경로> --target "<클래스>#<메서드>"

# 데모: LLM 호출 없이 대표 시나리오 재생
.venv\Scripts\python scripts\demo_golden.py

# 검증: 단위 테스트 (Docker·키 불필요)
.venv\Scripts\python -m pytest -q

# 검증: 통합 테스트 (Docker 필요, 키 불필요 — 저장된 호출 기록 재생)
.venv\Scripts\python -m pytest -m docker

# 개발용: 대표 시나리오의 LLM 호출 기록을 실제 모델로 다시 만들기 (키 필요)
.venv\Scripts\python scripts\record_golden.py --live
```
