# Code Test Agent 사용 가이드 — `cta` CLI

Java 코드 변경에 맞춰 JUnit 테스트를 자동으로 생성·유지보수하는 CLI 도구다.
이 문서만 보고 설치부터 실사용까지 따라할 수 있게 썼다.

## 1. 핵심 개념 — 3줄 요약

1. `cta generate 파일명.java`(파일 지정) 또는 `cta run`(git 변경에서 자동 판단)으로 테스트를 만든다
2. 생성물은 **바로 소스에 반영되지 않고 "제안"으로 보관**된다 — 격리된 Docker에서
   실행 검증 + 품질 게이트 5종을 통과한 결과물이다
3. `cta diff`로 검토하고 `cta apply`로 반영한다 — 코드에 손대는 건 언제나 사람의 명령이다

## 2. 준비물

| 항목 | 확인 |
|---|---|
| Python 3.11+ | `python --version` |
| Docker (실행 중) | `docker info` |
| 사내 게이트웨이 API 키 (`atl-...`) | 사내 안내 문서 |
| 대상 프로젝트 | Maven 단일 모듈, 기존 테스트 1개 이상 권장 |
| (선택) Neo4j | `cta run`의 "기존 테스트 찾기" 정확도 향상 — 6절 |

Java·Maven 설치 불필요 — 전부 Docker 컨테이너 안에서 돈다.

## 3. 설치 (최초 1회)

### 방법 A — 일반 사용: pip로 설치해 아무 폴더에서나 `cta` 실행

```powershell
# 1) cta 전용 가상환경을 홈에 만들고 설치한다
py -m venv $env:USERPROFILE\.cta
& $env:USERPROFILE\.cta\Scripts\pip install <리포지토리 경로 또는 git+사내git주소>
#   예: pip install C:\src\code-test-agent
#   예: pip install git+https://사내git/.../code-test-agent.git

# 2) cta를 PATH에 올린다 (현재 사용자, 새 터미널부터 적용)
[Environment]::SetEnvironmentVariable("Path",
  "$env:USERPROFILE\.cta\Scripts;" + [Environment]::GetEnvironmentVariable("Path", "User"), "User")
```

> pipx가 있다면 위 두 단계 대신 `pipx install <리포지토리 경로>` 한 줄로 끝난다.

### 방법 B — 개발 중: 리포지토리 안에서 편집 설치

```powershell
git clone <이 리포지토리> && cd <리포지토리>
python -m venv .venv
.venv\Scripts\pip install -e .          # 코드 수정이 바로 반영되는 개발 설치
.venv\Scripts\Activate.ps1
```

### 공통 — 설정 파일 `.env`

`cta`는 `.env`를 이 순서로 찾는다: **① 실행하는 폴더** → **② `~\.cta\.env`(전역)**.
자바 프로젝트마다 따로 둘 필요 없이 전역 한 곳이면 충분하다:

```powershell
New-Item -ItemType Directory -Force $env:USERPROFILE\.cta | Out-Null
notepad $env:USERPROFILE\.cta\.env     # 아래 3줄 입력 후 저장
```

```
CTA_GATEWAY_URL=      ← 게이트웨이 주소
CTA_GATEWAY_API_KEY=  ← 본인 API 키 (atl-...)
CTA_LLM_MODEL=gpt-5   ← 모델 (생략 시 gpt-4.1)
```

⚠️ 키가 든 `.env`는 어떤 저장소에도 커밋하지 않는다.

설치 확인: 새 터미널에서 `cta --help` 가 명령 목록을 보여주면 성공.

## 4. 기본 워크플로 — 생성 → 검토 → 반영

자바 프로젝트 폴더(또는 그 부모 폴더)에서 실행한다 — **`--project`는 안 써도 된다**:

```powershell
# ① 생성 — 파일 이름 하나면 된다 (최초 실행은 의존성 준비로 수 분, 이후 캐시로 ~1-2분)
cta generate OrderService.java

# ② 검토 — 제안이 1건이면 바로 diff, 여러 건이면 목록
cta diff

# ③ 반영 (또는 폐기) — 제안이 1건이면 이름 생략 가능
cta apply
cta discard
```

**인자를 생략하면 벌어지는 일**:
- 프로젝트: 현재 폴더→상위→하위 순으로 pom.xml을 찾아 자동 인식.
  하위에 여러 개면 번호로 고르게 한다 (좁히려면 `--project`)
- 파일: 현재 폴더 하위를 탐색해 찾고, 파일의 메서드 중 **기존 테스트가 이미
  다루는 메서드는 건너뛰고** 없는 것만 생성한다. private 메서드는 제외.
  건너뛴 것까지 전부 만들려면 `--all`
- apply/discard 이름: 대기 제안이 1건이면 그것. 여럿이면 이름이나 `--all`을 요구한다

특정 메서드 하나만 지정하고 싶을 때:

```powershell
cta generate --target "OrderService#cancel"
```

5분 체험(방법 B, 리포지토리 안): `cta generate Calculator.java --fast`

**생성 중 벌어지는 일**: LLM이 테스트 작성 → 인터넷 차단 Docker에서 컴파일·실행 →
실패하면 스스로 수정(같은 실패가 반복되면 멈추고 터미널로 질문 — Enter=계속,
s=중지, 텍스트=힌트) → 통과하면 게이트 5종 검사.
단계마다 경과 시간과 함께 진행 상황이 출력된다 — 주로 LLM 호출(수십 초)과
게이트의 coverage·mutation 검사(각각 별도 실행, 수십 초~수 분)에서 시간이 간다.
출력 형식 (수치는 실행마다 다름):

```
  [   0초] 정보 수집 — 대상 조사·비슷한 테스트 검색
  [   0초] 코드 생성 중 — LLM 호출 (1번째 시도, 수십 초 걸릴 수 있다)
  [   N초] 생성 완료 (n자, n초) → 파일 쓰기
  [   N초] 샌드박스 실행 중 — CalculatorDivideTest
  [   N초] 실행 끝 (n초) — 통과
  [   N초] 테스트 통과 — 품질 게이트 검사 시작
  [   N초] 게이트[coverage] 검사 중
  ...
```

| 게이트 | 잡아내는 것 |
|---|---|
| assert | 기존 검증을 지우거나 느슨하게 바꾼 경우 |
| skip | @Disabled 등으로 테스트를 꺼버린 경우 |
| scope | 테스트 폴더 밖(대상 코드 등)을 몰래 수정한 경우 |
| coverage | 대상 라인 80%·분기 70% 미달 (조정: 7절) |
| mutation | 일부러 심은 버그를 못 잡는 "빈 테스트" |

탈락 시 사유를 모델에게 돌려주고 재시도(기본 3회), 소진하면 "사람 확인 필요"
상태의 제안으로 남는다. **어느 경우든 apply 전에는 소스가 바뀌지 않는다.**

`generate` 주요 옵션: `--all`(파일 모드에서 기존 테스트가 다루는 메서드도 생성)
`--test-class`(이름 지정) `--instruction`(추가 요구) `--model`(모델 교체)
`--fast`(게이트 3종만, 빠름) `--non-interactive`(질문 생략)

## 5. 변경 기반 워크플로 — `cta run`

코드를 고친 뒤(커밋 전):

```powershell
cta run --message "쿠폰 중복 적용 버그 수정" --execute
```

에이전트가 ① git diff에서 바뀐 메서드를 찾고 ② 의도를 분류하고(버그 수정/
리팩터링/새 기능/불확실) ③ **규칙표**로 할 일을 정한다:

| 의도 | 기존 테스트 | 결정 |
|---|---|---|
| 버그 수정·새 기능 | — | 테스트 생성 → 제안 |
| 리팩터링 | 통과 | 할 일 없음 (동작 보존 확인) |
| 리팩터링 | **실패** | **사람에게 넘김** — 터미널에서 답해야 진행 |
| 불확실 | — | 사람에게 물음 |

옵션: `--execute` 없으면 결정만 출력 / `--intent bug_fix|refactor|new_feature`
(의도를 알면 지정 — LLM 분류 생략) / `--base HEAD~1`(커밋 범위) /
`--non-interactive`(CI: 사람 확인은 보고만)

## 6. (선택) 코드 그래프 — 기존 테스트를 실측으로 찾기

`cta run`이 "기존 테스트가 통과하는가"를 판단하려면 어떤 테스트가 그 메서드를
실행하는지 알아야 한다. 그래프를 만들어 두면 커버리지 **실측** 기반으로 찾는다:

```powershell
docker run -d --name cta-neo4j -e NEO4J_AUTH=neo4j/원하는암호 `
  -p 7687:7687 -p 7474:7474 neo4j:5
# .env에 추가: CTA_NEO4J_PASSWORD=원하는암호

cta graph --coverage
```

포트 두 개의 역할이 다르다:

- **7687 (Bolt)**: 에이전트가 그래프를 읽고 쓰는 드라이버 전용 포트. 브라우저로 열어도 아무것도 안 보인다
- **7474 (HTTP)**: 웹 UI(Neo4j Browser). 그래프를 눈으로 확인하려면 `http://localhost:7474` 로 접속한다

그래프가 없으면 "커버 테스트 없음"으로 보수적으로 동작한다(사람에게 묻는 쪽).
코드가 많이 바뀌면 다시 빌드한다.

그래프의 스키마·설계 이유·Browser에서 쓸 질의 예시는 `docs/코드그래프.md` 참조.

## 7. 게이트 기준치 조정 — `cta.toml`

대상 프로젝트 루트에 두면 기본값을 덮어쓴다:

```toml
[gates]
line_min = 0.9      # 기본 0.80
branch_min = 0.8    # 기본 0.70
max_retries = 2     # 기본 3
mutation_min = 0.6  # 기본 0.5
```

## 8. 문제가 생기면

| 증상 | 해결 |
|---|---|
| `cta` 명령을 못 찾음 | 방법 A: PATH 등록 후 **새 터미널** 열기 (임시로는 전체 경로 `~\.cta\Scripts\cta.exe`) / 방법 B: `.venv\Scripts\Activate.ps1` |
| `환경변수 ...가 필요하다` (설정을 못 찾음) | `.env` 위치 확인 — 실행하는 폴더 또는 `~\.cta\.env` (3절 공통) |
| `failed to connect to the docker API` | Docker Desktop 실행 후 재시도 |
| `환경변수 CTA_GATEWAY_URL·CTA_GATEWAY_API_KEY가 필요하다` | `.env` 확인 (3절) |
| `게이트웨이 호출 실패 ... 401/403` | API 키 재발급 후 `.env` 갱신 |
| 준비 단계가 수 분째 진행 | 정상 — 프로젝트당 최초 1회 (의존성+분석 도구 다운로드) |
| `뮤테이션 리포트 없음` 탈락 | 예전 캐시 — `<프로젝트>\.cta\m2repo` 삭제 후 재실행 |
| `제안 ... 이 없다` | `cta diff`로 이름 확인 (apply/discard는 목록의 이름 사용) |
| `환경변수 CTA_NEO4J_PASSWORD가 필요하다` | 6절 설정 (그래프 미사용 시 무시 가능) |
| 한글 깨짐 (Windows) | `$env:PYTHONIOENCODING='utf-8'` |

## 9. 명령 요약

프로젝트는 전 명령에서 자동 인식된다 — `--project`는 좁힐 때만 쓴다.

| 명령 | 역할 |
|---|---|
| `cta generate <파일명>` | 파일 탐색 → 테스트 없는 메서드에 생성 → 제안 보관 |
| `cta generate --target "C#m"` | 특정 메서드 하나만 지정해 생성 |
| `cta run [--execute]` | git 변경에서 자동 판단 → 생성 |
| `cta diff [이름]` | 제안 목록 / 코드 diff (1건이면 바로 diff) |
| `cta apply [이름|--all]` | 제안을 소스에 반영 (1건이면 이름 생략 가능) |
| `cta discard [이름|--all]` | 제안 폐기 (1건이면 이름 생략 가능) |
| `cta graph [--coverage]` | 코드 그래프 빌드 (Neo4j) |
| `cta demo` | 대표 시나리오 재생 시연 (LLM 비용 0) |
| `cta eval [--fast]` | 결함 세트 검출률 실측 (개발용) |
