# 개발 환경 — Claude Code 구현 킷

이 리포는 Claude Code로 3단계(PoC → 테스트·고도화 → E2E) 구현을 진행했다. 개발 규칙과 단계별 스킬은 아래 파일들에 있다.
(2026-09-06까지 루트 `README.md`에 있던 내용을 옮겼다 — README는 제품 소개로 바뀌었다.)

## 구성

```
CLAUDE.md                          # 항상 로드되는 규칙 (절대 규칙 R1~R7, DoD, 보고 형식)
.claude/skills/phase1-poc/         # 1단계: M0~M3, 수직 슬라이스 + poc-findings
.claude/skills/phase2-hardening/   # 2단계: M4~M7, 파이프라인·게이트·평가 하네스
.claude/skills/phase3-e2e/         # 3단계: M8, CLI·MCP·장기기억·릴리스
.claude/commands/done-check.md     # /done-check — DoD 실검증 후 4줄 보고
.claude/commands/poc-report.md     # /poc-report — poc-findings.md 생성·갱신
.claude/commands/phase-status.md   # /phase-status — 관문 대비 진행 점검
docs/E2E/                          # 3단계 계획·작업 목록·릴리스 체크리스트·작업 기록
```

## 개발 명령

```bash
pip install -e . pytest ruff            # 편집 설치 (Python 3.11+)
ruff check . && ruff format --check .   # 린트·포맷
pytest -q                               # 단위 테스트 (Docker·Neo4j 제외)
pytest -m docker / pytest -m neo4j      # 통합 테스트 (각각 Docker 데몬 / Neo4j 필요)
python scripts/check_defects.py         # 결함 세트 자기 검사 (로컬 JDK 17+)
```

CI(`.github/workflows/ci.yml`)는 `check`(ruff·pytest 재생 모드·결함 세트 자기 검사, Python 3.11/3.12)가 모든 push에,
`integration`(Docker·Neo4j)은 수동 실행이다. 저장된 LLM 호출 기록이 없으면 재생 테스트가 실패하는 것이 정상이다(R7).

## 추천 플러그인

공식 마켓플레이스는 자동 등록돼 있다. 설치: `/plugin install <이름>@claude-plugins-official`

### 1군 — 전 단계 필수

| 플러그인 | 왜 이 프로젝트에 |
|---|---|
| **pyright-lsp** | 타입 오류를 편집 중 실시간 감지. 타입 힌트가 DoD 4번이라 없으면 `/done-check`에서 뒤늦게 잡힌다 |
| **hookify** | 자연어로 훅 생성. DoD를 "지침"이 아니라 "자동 실행"으로 만드는 핵심 |
| **security-guidance** | 시크릿 유출·위험한 셸 호출 감시. 게이트웨이 토큰과 샌드박스를 다루므로 필수 |
| **code-review** | 커밋 전 diff 리뷰 서브에이전트. 층 분리·R규칙 위반을 사람 리뷰 전에 걸러낸다 |
| **commit-commands** | 논리 단위 소커밋 + 문서 병행 규칙을 커밋 시점에 점검 |
| **context7** | LangGraph·Neo4j·MCP SDK 최신 문서 주입. API가 자주 바뀌어 학습 데이터로 짜면 낡은 코드가 나온다(MCP SDK 2.x에서 실제로 겪었다) |

**hookify로 등록할 규칙**
```
/hookify 파이썬 파일을 수정한 뒤에는 항상 ruff check와 ruff format --check를 그 파일에 실행해줘
/hookify 작업을 마치기 전에 pytest -q를 실행하고, 실패하면 완료로 보고하지 마
/hookify core/ 아래 파일에 java, maven, junit, jacoco 문자열이 들어가면 경고해줘
/hookify -Dtest 인자 없는 mvn test 실행을 막아줘
```

### 2군 — 단계별 추가

| 단계 | 플러그인 | 왜 |
|---|---|---|
| 1 PoC | **feature-dev** | 계획→구현→검증 워크플로 |
| 1 PoC | **code-simplifier** | 완성 후 과한 추상화 제거 |
| 2 고도화 | **pr-review-toolkit** | 게이트·파이프라인처럼 안전에 직결되는 변경에 깊은 검토 |
| 2 고도화 | Neo4j MCP (커뮤니티 `neo4j-contrib/mcp-neo4j`) | Claude Code에서 직접 Cypher를 날려 그래프 상태 확인 |
| 3 E2E | **mcp-server-dev** | 우리 MCP 서버(`cta-mcp`) 검증 |
| 3 E2E | **claude-md-management** | CLAUDE.md가 코드와 어긋났는지 정기 점검 |

### 설치하지 않을 것과 이유

- **ralph-loop** (자율 반복 실행): 카파시 원칙·DoD와 정면 충돌. 이 프로젝트는 짧은 고삐가 원칙
- **jdtls-lsp** (Java LSP): 에이전트 코드는 Python. 대상 Java 프로젝트는 샌드박스 안에서만 만진다
- **Superpowers 류 대형 워크플로 프레임워크**: 자체 규칙이 CLAUDE.md와 충돌
- **frontend-design, playwright**: UI 없음

⚠️ 플러그인은 사용자 권한으로 코드를 실행하는 신뢰 컴포넌트다. 커뮤니티 것은 저장소·권한·외부 연결을 확인하고 설치한다.

## 이 PC에서 알아 둘 것 (Windows)

- 콘솔 인코딩이 cp949면 한글 출력이 깨질 수 있다 — `$env:PYTHONUTF8='1'`
- `datetime.now()` 해상도(~15ms)가 낮아 타임스탬프 파일명이 겹칠 수 있다(memos 결함으로 실제 발생, 순번으로 해결)
- Docker·게이트웨이가 없는 PC에서는 `pytest -q`(재생)와 `check_defects.py`(JDK)까지만 검증된다 — 그 이상은 "미검증"으로 보고
